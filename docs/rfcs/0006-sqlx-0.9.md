# Summary

Move rok-db from sqlx 0.8 to sqlx 0.9, which raises the minimum supported Rust version
from 1.85 to 1.94 (sqlx 0.9's own `rust-version`). Ship it in 0.5.0, together with the
other 0.5 changes, so users see one breaking release.

# Motivation

- sqlx 0.9 is the maintained line. Fixes and new database support (needed for the SQLite
  backend, RFC 0003) land there, and sqlx 0.8 gets no further releases.
- rok-db re-exports sqlx (`rok_db::sqlx`) and its types in model fields
  (`sqlx::types::Decimal`, `PgInterval`, `Json<T>`). Users can't mix sqlx 0.9 in their
  own code with a rok-db built on 0.8.

# Guide-level explanation

For code that only uses rok-db's API, nothing changes: models, queries, `raw()`, joins,
migrations and `rok-db-gen` work as before.

Code that calls sqlx directly through `rok_db::sqlx` must follow sqlx 0.9's rules. The
main one: `query()`, `query_as()`, `raw_sql()` and friends accept only `&'static str` or a
string wrapped in `AssertSqlSafe`, after you have checked it can't carry SQL injection:

```rust
use rok_db::sqlx::{self, AssertSqlSafe};

sqlx::query("SELECT 1").execute(&db).await?;              // literal: fine
sqlx::query(AssertSqlSafe(sql_built_from_trusted_parts))  // audited dynamic SQL
    .execute(&db)
    .await?;
```

# Reference-level explanation

- **Dependency.** `sqlx = "0.9"` with the same features (`runtime-tokio`, `postgres`,
  `macros`). `macros` also turns on sqlx-core's `offline` feature, which is what defines
  `Executor::describe`. rok-db implements `Executor` for `&Db` and `&mut Tx`, so that
  feature has to be on, or the impls would break as soon as another crate enabled it.
- **`Executor` impls** follow the new trait: `prepare_with` and `describe` take an owned
  `SqlStr`, and `PgStatement` has no lifetime parameter.
- **SQL strings.** Every statement rok-db sends is built by its SQL builder, which quotes
  identifiers and binds values, or is the developer's own migration SQL. These are wrapped
  in `AssertSqlSafe` where they reach sqlx. `rok_db::raw(sql)` keeps its signature: as
  before, it is the escape hatch for hand-written SQL with bound parameters.
- **MSRV** is 1.94. The CI MSRV job reads `rust-version`; the resolver setting in
  `.cargo/config.toml` keeps picking dependencies that build on it.
- **Lints.** Clippy's MSRV-aware lints now suggest `if let` chains and `is_multiple_of`,
  which are applied (no behaviour change).

# Drawbacks

- Users on Rust older than 1.94 must stay on rok-db 0.4.
- Direct sqlx calls in user code need `AssertSqlSafe` for dynamic strings.

# Rationale and alternatives

- **Stay on sqlx 0.8.** It keeps the old MSRV, but blocks the SQLite backend and leaves
  users unable to upgrade sqlx in their own code.
- **Upgrade in 0.6.0.** That means two breaking releases in a row; bundling it with 0.5.0
  means one.

# Prior art

SeaORM and other sqlx-based crates move their MSRV with sqlx's.

# Compatibility

Breaking for direct sqlx use and for the MSRV, which is allowed by a `0.y` minor release
and recorded in the changelog. rok-db's own API is unchanged.

# Unresolved questions

None.

# Future possibilities

sqlx 0.9's SQLite driver is the base for RFC 0003's SQLite backend.
